⏺ FitnessTrack is now a static PWA. There's no server or Docker container any
  more: the whole app, including its SQLite database, runs on the phone and
  works offline. Nothing is committed or pushed yet.

  How it works

  - Same logic, now running on the phone. The Express routes moved into
    client/src/backend/ with almost no changes. They run in the browser against
    SQLite compiled to WebAssembly (sql.js), through a small wrapper that mimics
    better-sqlite3. That's why the progression algorithm, recap, stats and
    migrations are untouched.
  - Saving: after every change, the database is written to the browser's
    on-device storage (IndexedDB) before the app shows the update. Database
    migrations run every time the app opens.
  - Offline: a service worker is generated at build time and caches the entire
    app, so it launches with no connection. When you deploy a new version, the
    installed app shows a "New version ready — tap to reload" bar.
  - No passwords: the first screen asks for a name and avatar, or lets you
    restore a backup.
  - Backups: Setup → Data has Export and Import. On phones these use the share
    sheet, which offers Save to Files or Drive.
  - Removed: the server, Docker files, systemd unit, setup/update scripts, and
    the in-app git pull updater.

  Verified

  - All existing test suites pass, plus a new 13-test end-to-end backend test
    that runs real SQLite in Node. It covers logging sets, progression, unlock,
    stats/CSV, export and import, reset/restore, and reopening from storage.
  - I drove the production build in headless Chrome at phone size:
    - Creating a profile and activating a plan worked, and the workout screen
      rendered fully.
    - A logged set survived a reload.
    - With the network turned off, the app relaunched, a change made offline was
      saved, and it was still there after another offline reload.

  I couldn't test on a real iPhone or Android device; the share-sheet export and
  the home-screen install are the parts that only a real phone will confirm.

  What you need to do

  1. Host it once over HTTPS. Service workers won't run on a plain http:// LAN
     address. I added .github/workflows/pages.yml: turn on repo Settings → Pages
     → Source: GitHub Actions, then push to master. It runs the tests and
     deploys to https://<user>.github.io/FitnessTrack/. Any static host works
     too, since all paths are relative.
  2. Install it: iPhone: Safari → Share → Add to Home Screen. Android: Chrome →
     Install app.
  3. Bring your existing data across:
     - Stop the container so SQLite folds its write-ahead log into the main
       file.
     - Copy the database out: docker compose cp app:/data/fitness.db .
     - Get the file onto your phone, then choose Restore from a backup file on
       the welcome screen.
     - If the old database had several accounts, the app asks which one is
       yours.

  Things to know

  - Your data exists only on that phone. Deleting the app or clearing the
    browser's site data deletes it, so export backups regularly. There's no sync
    between devices.
  - Dates are still in UTC, as they were on the server. In the Americas, an
    evening session can be dated the next day. This was true before too; I
    didn't change it.
  - Two open tabs don't share data: each keeps its own copy, and whichever saves
    last overwrites the other. That shouldn't come up with a single installed
    app.
  - Node version: Vite 8 needs Node 20.19 or newer, and your default node is
    v15. I used ~/.nvm/versions/node/v22.12.0.
